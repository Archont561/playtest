# Milestone M5: Polyglot Core Conformance & Cross-Language CLI (`v0.5.0`)

**Status**: Backlog  
**Target SemVer**: `0.5.0`  
**Packages**: Playtest implementations for Rust, Python, TypeScript, C++, C, C#, Go, Java, and R; shared Rust CLI (`playtest-cli`, first released in M1).

## Objective

Deliver the same observable core test capabilities across all nine supported language targets, using idiomatic language APIs, and provide one CLI for target detection, test orchestration, toolchain diagnostics, and normalized results. The contract is [Spec 0005](../specs/0005-polyglot-1-to-1-fixture-and-bdd-parity.md); this milestone and its tasks track implementation rather than redefining semantics.

The `playtest` binary already exists when this milestone starts: M1 ships it with `version`, `init`, and `sync` ([ADR 0015](../adr/0015-cli-first-distribution-and-five-crate-workspace.md)). M5 adds the orchestration commands `list`, `doctor`, `test`, `coverage`, and `mutation`, the reporters through which each SDK reports from inside its native runner ([ADR 0018](../adr/0018-sdk-reporters-and-report-protocol.md)), and SDK mirrors for the targets that M1 does not cover.

## Deliverables & Acceptance Criteria

- [ ] **Core feature parity in all nine targets**:
  - Fixture injection and documented scopes; unused fixtures are not created.
  - Strict LIFO teardown continues after assertion/test and cleanup failures.
  - Code-first BDD state flow through Given → When → Then → And.
  - Property testing uses fresh per-sample fixture lifecycles, shrinking, and reproducible failing cases.
  - Skip/conditional skip and table-driven or generated cases have clear outcomes.
  - Shared isolation and deterministic helpers defined in Spec 0004 have equivalent behavior.
- [x] **Cross-language conformance suite** (`task_023`): the suite, the manifest, and the matrix exist.
  - `backlog/conformance.yml` declares every Spec 0005 §1 capability and, per language target, the suite that proves it.
  - `python -m automation.conformance_cli check` runs the suites and reports the `(capability x target)` matrix; `--require-full` exits 1 while any required cell is not passing.
  - `--gate` is the CI policy and runs unattended in the `conformance` job: a cell may be `pass` or `unavailable`, but a `fail` is a defect and a suite that claims a capability yet reports `not_implemented` proves nothing, so both fail the build.
  - A cell is `pass` only when a suite ran and exited zero; an unclaimed target is `not_implemented`, never green. A missing toolchain reports `unavailable`, not `fail`.
  - Every required capability in Spec 0005 §1.1 and §1.4 is now claimed by at least one target: explicit resolution, LIFO teardown, failure-safe teardown, and a skip outcome that carries a reason. The two optional capabilities (BDD state passthrough, fresh property samples) remain unclaimed until M3.
  - Runs shared behavior cases for the targets that implement the contract: **Rust, Python, TypeScript, and Go**. C++, C, C#, Java, and R declare no suite yet, so they report `not_implemented` — full parity is not claimed.
- [ ] **Workspace detection and runner mapping**:
  - Detects Rust (`Cargo.toml`), Python (`pyproject.toml`), TypeScript (`package.json`), C/C++ (CMake configuration and target language), C# (`*.csproj`/solution), Go (`go.mod`), Java (`pom.xml`/Gradle), and R (`DESCRIPTION`).
  - Resolves project-relative paths and selects each target's documented native runner.
- [ ] **Toolchain compatibility (`playtest doctor`)**:
  - Checks minimum supported Rust, Python, Bun/Node, C and C++ compilers, .NET, Go, Java, and R toolchains.
  - Reports missing/incompatible tools with actionable remediation; distinguishes required from optional tools.
- [ ] **Unified test execution and reporting (`playtest test`)**:
  - Runs all detected targets or a selected target/filter.
  - Aggregates process/test outcomes and normalized LCOV into documented terminal, JSON, and JUnit XML reports.
- [ ] **SDK reporters and report protocol ([Spec 0014](../specs/0014-report-protocol-and-runner-orchestration.md), [ADR 0018](../adr/0018-sdk-reporters-and-report-protocol.md))**:
  - Every SDK has a reporter for its native runner. It is silent unless the CLI switches it on, and no SDK ships a runner of its own.
  - `playtest test` starts all selected targets at once and combines each runner's exit status, the reporter's records, and the runner's own report.
  - A crash is reported at the test that was running. A target that produced no evidence does not pass. An SDK whose version or protocol differs from the CLI's ends the run with exit status 3.
- [ ] **SDK mirrors for the remaining targets ([Spec 0013 §4](../specs/0013-workspace-configuration-and-sdk-mirrors.md))**:
  - `playtest sync` writes a Go mirror. The mirror form and wiring of C#, Java, R, C, and C++ are designed, recorded, and covered by offline install tests, or the target is documented as registry-only.
- [ ] **Machine-consumable and extensible CLI contract ([Spec 0008](../specs/0008-cross-language-cli-and-toolchain-detection.md) §§6–8, [ADR 0012](../adr/0012-machine-consumable-and-extensible-cli-contract.md))**:
  - Semantic exit statuses (0/1/2/3), versioned JSON documents, and non-interactive stream discipline.
  - Explicit `--lang`/`--tier`/`--filter` selection of an unavailable target fails with remediation (exit 3) instead of skipping green; tiers (`unit`, `smoke`) map to native marker/filter mechanisms.
  - `playtest doctor` folds consumer-registered compatibility probes into the unified report under built-in rules.
  - A shipped consumer agent skill documents the contract, reachable from `playtest version` and command help.
- [ ] **Delegated coverage collection (`playtest coverage`, [Spec 0015](../specs/0015-coverage-collection-and-reporting.md))**:
  - Each selected target's documented native instrumentation runs; LCOV tracefiles are normalized and merged into one report.
  - Merged output matches the `automation/merge_lcov.py` baseline for the same inputs; targets that produced nothing are reported as `no_coverage`, never omitted.
  - `--min-lines` and `--min-branches` threshold enforcement with exit 1; an explicitly selected target without a coverage tool fails with remediation.
- [ ] **Delegated mutation quality gate (`playtest mutation`, [Spec 0011](../specs/0011-delegated-mutation-testing.md))**:
  - Each selected target's documented native mutator runs; normalized, schema-versioned score aggregation across targets.
  - `--min-score` threshold enforcement with surviving-mutant locations; explicitly requested engines that are missing fail with remediation.
