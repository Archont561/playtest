# Milestone M5: Polyglot Core Conformance & Cross-Language CLI (`v0.5.0`)

**Status**: Backlog  
**Target SemVer**: `0.5.0`  
**Packages**: Playtest implementations for Rust, Python, TypeScript, C++, C, C#, Go, Java, and R; shared Rust CLI.

## Objective

Deliver the same observable core test capabilities across all nine supported language targets, using idiomatic language APIs, and provide one CLI for target detection, test orchestration, toolchain diagnostics, and normalized results. The contract is [Spec 0005](../specs/0005-polyglot-1-to-1-fixture-and-bdd-parity.md); this milestone and its tasks track implementation rather than redefining semantics.

## Deliverables & Acceptance Criteria

- [ ] **Core feature parity in all nine targets**:
  - Fixture injection and documented scopes; unused fixtures are not created.
  - Strict LIFO teardown continues after assertion/test and cleanup failures.
  - Code-first BDD state flow through Given → When → Then → And.
  - Property testing uses fresh per-sample fixture lifecycles, shrinking, and reproducible failing cases.
  - Skip/conditional skip and table-driven or generated cases have clear outcomes.
  - Shared isolation and deterministic helpers defined in Spec 0004 have equivalent behavior.
- [ ] **Cross-language conformance suite**:
  - Runs shared behavior cases against Rust, Python, TypeScript, C++, C, C#, Go, Java, and R.
  - Reports pass/fail per language and capability; full parity is not reported until every required cell passes.
- [ ] **Workspace detection and runner mapping**:
  - Detects Rust (`Cargo.toml`), Python (`pyproject.toml`), TypeScript (`package.json`), C/C++ (CMake configuration and target language), C# (`*.csproj`/solution), Go (`go.mod`), Java (`pom.xml`/Gradle), and R (`DESCRIPTION`).
  - Resolves project-relative paths and selects each target's documented native runner.
- [ ] **Toolchain compatibility (`playtest doctor`)**:
  - Checks minimum supported Rust, Python, Bun/Node, C and C++ compilers, .NET, Go, Java, and R toolchains.
  - Reports missing/incompatible tools with actionable remediation; distinguishes required from optional tools.
- [ ] **Unified test execution and reporting (`playtest test`)**:
  - Runs all detected targets or a selected target/filter.
  - Aggregates process/test outcomes and normalized LCOV into documented terminal, JSON, and JUnit XML reports.
- [ ] **Machine-consumable and extensible CLI contract ([Spec 0008](../specs/0008-cross-language-cli-and-toolchain-detection.md) §§6–8, [ADR 0012](../adr/0012-machine-consumable-and-extensible-cli-contract.md))**:
  - Semantic exit statuses (0/1/2/3), versioned JSON documents, and non-interactive stream discipline.
  - Explicit `--lang`/`--tier`/`--filter` selection of an unavailable target fails with remediation (exit 3) instead of skipping green; tiers (`unit`, `smoke`) map to native marker/filter mechanisms.
  - `playtest doctor` folds consumer-registered compatibility probes into the unified report under built-in rules.
  - A shipped consumer agent skill documents the contract, reachable from `playtest version` and command help.
