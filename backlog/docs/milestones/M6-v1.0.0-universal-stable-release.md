# Milestone M6: Universal Stable Production Release (`v1.0.0`)

**Status**: Backlog  
**Target SemVer**: `1.0.0`  
**Targets**: All nine language ecosystems: Rust, Python, TypeScript, C++, C, C#, Go, Java, and R.

## Objective

Finalize and document stable APIs across all targets, verify the core behavioral parity contract in Spec 0005, complete the documentation portal and compatibility matrix, and coordinate production publication across the supported registries.

## Deliverables & Acceptance Criteria

- [ ] Stable, documented public APIs and versioning guarantees for all nine language targets.
- [ ] Every required capability in Spec 0005 passes the cross-language conformance suite for all nine targets.
- [ ] Comprehensive documentation portal with verified examples for every target and an honest feature-status matrix.
- [ ] Performance benchmarks for supported fixture implementations, with claims limited to measured results.
- [ ] CI verifies each target's declared toolchain/platform support, including minimum supported versions.
- [ ] Coverage gates and reports are defined consistently across all supported targets; target-specific gaps are reported rather than hidden by aggregation.
- [ ] **Fixture extension API frozen ([Spec 0010](../specs/0010-fixture-extension-api.md), [ADR 0014](../adr/0014-v1-stability-boundary-and-fixture-extension-model.md))**:
  - Extension points (registration, scopes, requested-only resolution, composition, failure-safe LIFO, diagnostics, discovery) implemented for Rust, Python, and TypeScript — the hosts of the ecosystem package family.
  - A dependency-free in-repo clap canary validates the surface end to end without core-internal APIs; any canary access to private APIs blocks the freeze.
  - Post-1.0 evolution of the extension surface is SemVer-additive only: `v1.0.0` is the stability boundary for core and extension contract alike; core releases after 1.0 are fixes-only.
- [ ] Coordinated release workflow publishes the artifacts each target supports: crates.io, PyPI, npm, NuGet, Maven Central, Go proxy/pkg.go.dev, Conan/GitHub Releases, and CRAN as configured. The release has one version across the CLI and every SDK ([ADR 0015](../adr/0015-cli-first-distribution-and-five-crate-workspace.md)).
- [ ] **Freeze questions raised by the CLI-first model are settled before the freeze** (`task_066`):
  - How "core releases after 1.0 are fixes-only" ([ADR 0014](../adr/0014-v1-stability-boundary-and-fixture-extension-model.md)) applies when a CLI feature release also raises every SDK's version number (ADR 0015, open question 2).
  - Whether the report protocol is frozen at `v1.0.0` ([ADR 0018](../adr/0018-sdk-reporters-and-report-protocol.md), open question 4).
- [ ] **Runner neutrality is decided before the freeze** (`task_065`): [ADR 0019](../adr/0019-runner-neutral-test-declaration-for-pure-runners.md) is Proposed. If it is accepted, tests are declared through Playtest's own API, a runner-adapter surface is frozen with the core, and a Python `unittest` adapter validates it. If it is rejected, nothing changes, and a runner that ships with a language can be added after v1 only with a new major version of the affected SDKs.
