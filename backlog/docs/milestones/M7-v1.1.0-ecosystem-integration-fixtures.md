# Milestone M7: Ecosystem Integration Fixtures (`v1.1.0`)

**Status**: Backlog  
**Target SemVer**: `1.1.0`  
**Targets**: First-party provider packages for Rust, Python, and TypeScript, built on the frozen Fixture Extension API ([Spec 0010](../specs/0010-fixture-extension-api.md)); tier/CLI support from the shared `playtest` CLI.

## Objective

Open the post-v1 era where **only ecosystem work ships**: every deliverable is a separate fixture package — independently versioned, released as its own artifact, and reported separately from core parity — built exclusively on the extension surface that [ADR 0014](../adr/0014-v1-stability-boundary-and-fixture-extension-model.md) freezes at `v1.0.0`. The fixture behaviors are specified in [Spec 0009](../specs/0009-ecosystem-integration-fixtures.md); [ADR 0013](../adr/0013-scoped-browser-drop-and-ecosystem-integration-fixtures.md) records the browser/webview scoping relative to ADR 0004. Core packages receive no feature work in this milestone.

## Deliverables & Acceptance Criteria

- [ ] **`playtest-clap` (Rust, graduates the canary)**:
  - Published crate providing `cli_app`: in-process `CommandFactory` runs, captured output/status, snapshot goldens, failure-safe spawned-binary mode.
  - Written against the public Spec 0010 surface only; core manifests unchanged.
- [ ] **`playtest-tui` (Rust)**:
  - Headless `TestBackend` default with direct or snap-asserted buffers; injected input; clock-driven frame stepping; real-terminal mode fail-loud without a tty.
- [ ] **`playtest-tauri` (Rust)**:
  - In-process host (commands/state/plugins) as the always-runnable default; opt-in real-host mode for desktop webviews and mobile emulator sessions following the qualification-harness pattern.
  - Doctor probes for webview runtimes and mobile emulators; nothing heavyweight in core installs.
- [ ] **`playtest-qt` (Python)**:
  - Process-singleton `QApplication` host (PyQt6/PySide6), offscreen by default, per-test windows with failure-safe LIFO teardown, clock-driven event pumping.
  - Explicitly requested run without a usable Qt platform fails with remediation instead of skipping green.
- [ ] **`playtest-tk` (Python)**:
  - Fresh withdrawn `Tk` root per test, destroyed failure-safe in LIFO order; `after`-based clock-driven pumping.
  - Missing Tk support under explicit request fails with remediation.
- [ ] **`@archont561/playtest-browser` (TypeScript)**:
  - Playwright as optional peer dependency; fresh context per test with failure-safe LIFO closure; deterministic waiting for client-side JavaScript.
  - Missing browser under explicit selection fails with remediation; network routing mapped to `cassette`/`network_guard` semantics.
- [ ] **Integration tiers, releases, and reporting**:
  - `gui`, `browser`, and `mobile` tiers declared, mapped per target, and visible in `playtest list`.
  - Doctor probes for Qt platform, tkinter presence, browser binaries, Tauri webview runtimes, and mobile emulators.
  - Release-pipeline slots and docs-portal sections exist for each provider package; core releases stay fixes-only.
  - Provider conformance results reported separately from Spec 0005 core parity.
